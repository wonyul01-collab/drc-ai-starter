# 디알컴퍼니 작업 규칙 (직원 공통)

클로드는 이 폴더에서 일할 때 아래 규칙을 항상 지킨다.

## 말하는 방식
- 한국어로, 결론 먼저, 짧고 구조적으로. 전문어는 쉬운 말로 풀어 쓴다.
- 일을 시작하기 전에 "무엇을 · 어디에 · 어떻게" 만들지 3줄로 먼저 말한다.

## 자동화 개발 6단계 (회사 표준, 자세한 것은 스킬 '자동화개발')
1. 요구: 지금 손으로 하는 일을 순서대로 적고, 끝 모습(화면·엑셀·메일)을 정한다.
2. 수집: 공식 API → 엑셀 내려받기 자동화 → 사이트 자동 조작(Playwright) 순서로 고른다.
3. 계산·화면: 계산 코드는 하나만 둔다(화면 숫자 = 메일 숫자 = 엑셀 숫자).
4. 게시: 같은 주소에 다시 올린다. 새 주소를 만들지 않는다.
5. 자동 실행: 작업 스케줄러에 등록하고 '마지막 실행 결과 0'과 결과 파일 시각까지 확인한다.
6. 점검: 원본 합계와 대조하고, 실패하면 알림이 오게 만든다.

## 안전 규칙 (반드시)
- 비밀번호·API 키는 `.env` 파일에만 쓴다. 코드·채팅·화면·깃허브에 직접 쓰지 않는다.
- `.env`, 고객 주문 파일, 실적 원본은 `.gitignore`에 넣어 깃허브에 올리지 않는다.
- 고객 개인정보(이름·전화·주소)가 든 파일은 다른 사람과 공유하거나 외부 사이트에 올리지 않는다.
- 파일 삭제·이동·이름 바꾸기, 메일·문자 발송, 결제, 공개 게시는 실행 전에 사람에게 확인받는다.
- 고치기 전에 `git commit`으로 저장점을 남긴다(되돌릴 수 있게).
- 동시 접속이 1명뿐인 사이트(사방넷·이카운트 등)는 수집 중에 다른 직원이 튕길 수 있으니 시험은 내려받기 없이 한다.

## 화면 기준 (자세한 것은 스킬 '화면기준')
- 왼쪽 = 업무 묶음, 위 탭 = 진행 순서, 한 화면 안에서 처리(세로로 길게 내리기 금지).
- 글씨 본문 15px 이상, 수치는 그래프·설명은 표, 글꼴 Pretendard.
- 둥근 카드+그림자, 알약 단추, 이모지, 보라·파랑 그라디언트, 방사형 빛줄기 무늬 금지.
